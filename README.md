# وصال | WISAL

موقع عربي للبحث عن رحلات تاركو وبدر وسودانير، مبني بالكامل بـ **Next.js 16 App Router وReact 19 وTypeScript**. الواجهة وواجهات API ومحرك البحث تعمل على Node.js؛ لا توجد خدمة Python أو Flask.

## التشغيل المحلي

يتطلب Node.js 24 أو أحدث. ثبّت الاعتماديات والمتصفح مرة واحدة:

```sh
npm ci
npm run browser:install
npm run dev
```

افتح http://localhost:3000. يستخدم محرك البحث الإصدار المجاني المثبّت `146.0.7680.177.5` من Chromium و`cloakbrowser@0.6.2`، دون مفتاح API أو ترخيص Pro. لتثبيت النسخة نفسها محليًا، اضبط `CLOAKBROWSER_VERSION=146.0.7680.177.5` و`CLOAKBROWSER_AUTO_UPDATE=false` قبل أمر التثبيت. على Linux ثبّت اعتماديات النظام أيضًا:

```sh
npx playwright-core install-deps chromium
```

للتشغيل الإنتاجي محليًا:

```sh
npm run build
npm start
```

## بنية المشروع

- `app/`: الصفحة الرئيسية، `/results`، وواجهتا `/api/search` و`/api/health`.
- `components/`: مكونات React للنموذج والنتائج والتصميم العربي المتجاوب.
- `lib/search.ts`: معايير البحث والتحقق منها وروابط الحجز المشتركة بين الواجهة والخادم.
- `lib/parse-results.ts`: قراءة صفوف الرحلات والأسعار الفعلية.
- `lib/search-airlines.ts`: جلسات CloakBrowser المعزولة لكل شركة، والمهل وإعادة المحاولة والتنظيف.
- `lib/rotate-proxy.ts`: تدوير بروكسيات SOCKS4 الاحتياطية من قائمة Proxifly، والتحقق منها وتخزينها مؤقتًا.
- `lib/search-service.ts`: إدارة الطلبات المتزامنة وذاكرة النتائج المؤقتة.
- `test/fixtures/`: لقطات نتائج حقيقية رُصدت في 2026-10-14، للاختبارات فقط.

تُحوّل الروابط القديمة `/index.html` و`/results.html` إلى المسارات الجديدة مع الاحتفاظ بمعايير البحث.

## البحث والأسعار

الجنيه السوداني (SDG) هو العملة الافتراضية. يمكن اختيار الريال السعودي (SAR) أو الدولار الأمريكي (USD). تُرسل العملة إلى الشركة، وتُقرأ الأسعار بعملتها الأصلية دون تحويل تقديري أو ضرب السعر في عدد المسافرين. إذا لم تدعم الشركة العملة، تظهر رسالة خاصة بها. يجب تأكيد الإجمالي وشروط السعر لدى الشركة عند الحجز، خصوصًا للذهاب والعودة.

تقرأ خدمة البحث صفحات الحجز العامة من خلال حزمة JavaScript من CloakBrowser. لا تُنفّذ حجزًا أو تسجيل دخول، ولا تحفظ جلسات الشركات. لا تُعرض أسعار احتياطية أو مختلقة عند تعذّر الاتصال. أسعار الأيام المجاورة في تقويم الشركة لا تُعامل كرحلات للتاريخ المطلوب.

يبدأ البحث باتصال مباشر، بمهلة مستقلة لكل مصدر تصل إلى 35 ثانية، ومحاولة إضافية واحدة للأخطاء المؤقتة. عند 403 أو أخطاء الشبكة أو انتهاء المهلة، ينتقل إلى بروكسيين مختلفين كحد أقصى من [قائمة Proxifly SOCKS4](https://cdn.jsdelivr.net/gh/proxifly/free-proxy-list@main/proxies/protocols/socks4/data.json). يُغلق المتصفح قبل تغيير البروكسي، وتُعاد فقط المصادر المتأثرة مع الاحتفاظ بنتائج الشركات الناجحة. مهلة كل مصدر عبر البروكسي تصل إلى 12 ثانية ضمن ميزانية إجمالية للعملية تقارب 80 ثانية. لا تُستخدم البروكسيات لإعادة طلبات 401 أو 429، أو عند عدم وجود رحلات أو عدم دعم العملة.

تُجلب قائمة البروكسيات عند الحاجة فقط، وتُخزّن لخمس دقائق. تُقبل عناوين IPv4 العامة وSOCKS4 فقط، ويُستبعد البروكسي الفاشل لخمس دقائق. تبقى شهادة HTTPS مطلوبة؛ لا يُعطّل التحقق منها. إذا تعطلت القائمة أو لم ينجح أي بروكسي، تظهر حالة المصدر وروابط الشركة دون أسعار بديلة. البروكسيات العامة قد تتعطل أو تكون محظورة أيضًا؛ وجودها في القائمة لا يضمن عملها. تتضمن النتائج `connection` و`proxyAttempts` للتشخيص دون كشف عناوين البروكسيات.

رسائل أخطاء المتصفح وعناوين الجلسات والبروكسيات لا تُسجّل ولا تُرسل إلى الواجهة. قد ترجع API استجابة HTTP 200 مع تعذّر بعض المصادر؛ راجع `sources[].status` لتقييم النتيجة.

تُخزّن الاستجابات المكتملة الناجحة في ذاكرة عملية Node.js لمدة 30 ثانية، مع الاحتفاظ بوقت التحقق الأصلي. يُسمح بعملية بحث واحدة لكل نسخة خادم، ويُعاد 429 مع `Retry-After` عند الانشغال. هذه الحدود والذاكرة محلية لكل نسخة، ولا تُشارك بين نسخ Vercel.

## Vercel وDocker

يحتفظ `vercel.json` بمسار نشر الحاوية الحالي ومنطقة `fra1`، وتعمل الحاوية الآن بخادم Next.js مستقل وNode.js بدل Python. يُثبَّت المتصفح واعتماديات Chromium أثناء البناء حتى لا يُنزّلا أثناء طلبات البحث. تشغيل حاويات Vercel متاح حاليًا كميزة Beta؛ راجع [وثائق Vercel](https://vercel.com/docs/functions/runtimes/container).

```sh
docker build -f Dockerfile.vercel -t rihla-next .
docker run --rm -p 3000:3000 rihla-next
```

فحص الصحة: `GET /api/health`. البحث: `GET /api/search?from=PZU&to=CAI&date=YYYY-MM-DD&passengers=1&trip=oneway&airline=badr&currency=SDG`.

## التحقق

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
```

اختبار المتصفح يشغّل نسخة الإنتاج تلقائيًا، ويفحص التنقل والتحقق من النموذج والعملات والفلاتر والجوال باستخدام استجابات اختبار معزولة داخل المتصفح. لا تُستخدم هذه الاستجابات في تشغيل الموقع. لاختبار المصادر الفعلية شغّل الخادم ثم:

```sh
npm run test:live
```

يمكن ضبط `TEST_BASE_URL` و`TEST_DATE` للاختبار الحي. يفحص GitHub Actions الأنواع والاختبارات والبناء ومسار المتصفح. الاختبار الحي وبناء الحاوية متاحان عبر تشغيل workflow يدويًا بخيار `live`؛ فهما يعتمدان على إتاحة مواقع الشركات.

# رحلة | Rihla

موقع عربي من صفحتين لبحث رحلات تاركو وبدر وسودانير، وقراءة مواعيدها وأسعارها من صفحات الحجز العامة باستخدام CloakBrowser.

## طريقة العمل

تُرسل المدن والتواريخ وعدد البالغين إلى خدمة البحث. تفتح الخدمة جلسة متصفح مستقلة لكل شركة عبر رابط SearchResult الصحيح، وتقرأ صفوف الرحلات الفعلية. لا تنفذ حجزًا أو تسجيل دخول، ولا تحفظ جلسات الشركات أو تعرض أسعارًا احتياطية.

روابط SearchFlights القديمة أعادت أخطاء عند فتحها مباشرة. في 2026-10-14 أمكن فتح نماذج الحجز والنتائج باستخدام CloakBrowser بعد استخدام نقطة الدخول الصحيحة. صفحات النتائج ترسل X-Frame-Options: SAMEORIGIN؛ لذلك تُقرأ في الخادم وتُعرض البيانات في بطاقات الموقع بدل تضمين الصفحات في iframe.

الأسعار كما تظهر في المصدر، دون ضرب تقديري في عدد المسافرين. ينبغي مراجعة الإجمالي وشروط السعر عند إتمام الحجز، خصوصًا للذهاب والعودة. أسعار الأيام المجاورة في تقويم الشركة لا تُعامل كرحلات للتاريخ المختار. إذا تغيّرت بنية الصفحة أو تعذّر الوصول، تظهر رسالة للشركة المتأثرة دون نتائج مختلقة.

## التشغيل

Dockerfile.vercel يثبت حزمة CloakBrowser 0.6.2 واعتماديات Chromium وينزل النسخة الرسمية مع تحقق التوقيع أثناء البناء. لا يحتاج إلى مفتاح API للشركات أو ترخيص Pro.

```sh
docker build -f Dockerfile.vercel -t rihla-live .
docker run --rm -p 3000:3000 rihla-live
```

افتح http://localhost:3000. تستخدم Vercel خدمة container واحدة للواجهة وAPI، وتحافظ على رابط المشروع الحالي. فحص صحة الخدمة: /api/health. البحث: /api/search.

## التحقق

```sh
python -m unittest discover -s test -p '*_test.py'
node test/search-links.test.js
node --check dist/app.js
```

الملفات تحت test/fixtures لقطات اختبار لنتائج حقيقية تم رصدها في 2026-10-14، ولا تُستخدم في تشغيل الموقع أو كبديل لتعذّر الاتصال. يختبر CI بناء الحاوية واستجابة بحث فعلية في تشغيل منفصل.

تُحفظ النتائج الناجحة في ذاكرة الخدمة لمدة 30 ثانية، حسب معايير البحث كاملة، وتعرض الواجهة وقت التحقق الأصلي. تُحدَّد جلسات البحث المتزامنة لتجنب إطلاق عدد غير محدود من المتصفحات.
